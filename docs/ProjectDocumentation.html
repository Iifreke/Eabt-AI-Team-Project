School RAG Agent

Technical Documentation & Architecture Overview

Next.js / Vite Supabase pgvector OpenRouter (Claude) Zoho CRM

1. Executive Summary

The School RAG Agent (Skylar) is a production-ready, AI-powered support and admissions chatbot designed specifically for educational institutions like Babcock School and ABU. Deployed entirely on Vercel, the platform seamlessly integrates an embeddable website widget, a robust Retrieval-Augmented Generation (RAG) backend API, and a centralized React-based Admin Dashboard. It autonomously handles visitor inquiries, captures lead details, triggers real-time escalations for complex queries, and synchronizes data with Zoho CRM.

2. System Architecture

Embeddable Widget

Built with React + Vite and compiled to a single widget.js IIFE. It can be embedded on any partner school's website using a single <script> tag. The widget supports dynamic theming based on the school's brand guidelines.

Serverless API

Located in the api/ directory, these Vercel serverless functions handle the chatbot's logic. LLM inference is driven by OpenRouter (Claude-3.5-Sonnet), while vector embeddings are generated directly via OpenAI (text-embedding-3-small).

Admin Dashboard

A secure React Single Page Application (SPA) utilizing Vite and Tailwind CSS. It allows administrators to manage knowledge base documents across multiple schools, monitor live chats, and intercept escalated conversations in real-time.

Database & Storage

Powered by Supabase (PostgreSQL). Features native pgvector support for semantic search over chunked document embeddings, relational tables for lead tracking, and secure object storage for uploaded PDFs/TXTs.

3. Key Integrations

  • AI Models: anthropic/claude-sonnet-4-5 via OpenRouter for conversational reasoning, and text-embedding-3-small via OpenAI for document embeddings.
  • Zoho CRM: Once a visitor completes the onboarding phase (providing Name, Email, and Phone), their data is automatically synced to Zoho CRM as a Lead via an offline refresh token system.
  • Resend API: Automatically dispatches email notifications to designated school administrators whenever a chat is flagged for escalation.

4. The "Skylar" Persona

The AI Agent operates under the persona Skylar. The system prompts instruct the LLM to behave as a warm, knowledgeable, and helpful human admissions assistant. It collects necessary lead information incrementally during an "onboarding" phase before switching to an "active" phase where it utilizes RAG to answer specific school-related queries without hallucinating details.

5. Embedding the Widget

To integrate Skylar onto a school's website, insert the configuration object and the script tag just before the closing </body> tag.

Babcock School Configuration

<script>
  window.SchoolBotConfig = {
    schoolId: 'backock',
    apiUrl: 'https://your-project.vercel.app',
    theme: {
      primaryColor: '#1a73e8',
      name: 'Backock School'
    }
  };
</script>
<script src="https://your-project.vercel.app/widget.js" async></script>

6. Environment Variables Configuration

The application requires the following environment variables to function correctly in both local development (.env) and Vercel environments:

Variable Description / Purpose
SUPABASE_URL & VITE_SUPABASE_URL The core Supabase project URL used by both the server and browser.
SUPABASE_SERVICE_KEY Service role key for administrative DB tasks (server-side only).
SUPABASE_ANON_KEY & VITE_SUPABASE_ANON_KEY Anon key used for client-side authentication and queries.
OPENROUTER_API_KEY OpenRouter key for accessing Claude-3.5-Sonnet completions.
OPENAI_API_KEY OpenAI key utilized exclusively for generating text embeddings.
ZOHO_CLIENT_ID, ZOHO_CLIENT_SECRET, ZOHO_REFRESH_TOKEN Credentials necessary for the Zoho CRM Lead synchronization.
RESEND_API_KEY API Key for sending escalation email alerts to administrators.
APP_URL & VITE_API_URL The root domain URL of the deployed application.

7. Setup and Deployment Workflow

The project is optimized for deployment on Vercel. The root package.json contains unified build scripts that compile the Widget and Admin panel, seamlessly moving the built widget.js artifact into the public admin/dist folder so it is served by the Next.js/Vercel architecture.

  1. Initialize the Supabase database using the SQL schema found in src/db/migrations/001_schema.sql.
  2. Create a private Supabase Storage bucket named documents.
  3. In Vercel, set the Build Command to npm run build and the Output Directory to admin/dist.
  4. Inject all necessary Environment Variables and execute the deployment.
