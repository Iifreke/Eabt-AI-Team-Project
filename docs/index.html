📋 Project Overview

The School RAG Agent (Skylar) is a state-of-the-art admissions and student support AI assistant. Deployed as a serverless platform on Vercel, it features a dynamically-themed website widget, an API backend powering Retrieval-Augmented Generation (RAG) using vector search, a Zoho CRM lead synchronization system, and a comprehensive Multi-Admin Dashboard.

🤖

RAG AI Pipeline

Generates responses grounded directly in school-specific documents using text-embedding-3-small embeddings and OpenRouter (Claude-3.5-Sonnet).

🚨

Human Escalation

Tracks visitor intent and triggers live chat handoffs, allowing staff to intercept and respond to prospective students in real time.

🏫

Multi-School Isolation

Supports multiple universities (Babcock and ABU) from a single deployment with complete database and knowledge base indexing isolation.

Quick Architecture Context: The frontend widget is built in React + Vite, compiled to a single IIFE bundle (widget.js), and served as a static asset. The API utilizes Node.js serverless functions under api/.

1. Clone the Repository & Configure Env

Clone the code: git clone <repo-url>. Copy .env.example to .env in the project root and fill in your API credentials.

2. Run Supabase Database Migrations

Copy the contents of src/db/migrations/001_schema.sql, 002_agent_metrics.sql, and 003_tickets.sql and execute them in your Supabase project's SQL Editor.

3. Create Supabase Storage Bucket

Navigate to Storage in Supabase, create a new private bucket named documents. Limit upload size to 10MB, and allow PDF, DOCX, and TXT mime types.

4. Install Node Dependencies

Run npm install in the root folder to pull dev tools and core runtime packages (OpenAI, Supabase JS, Resend, mammoth, etc.).

6. Run Local Vercel Server & Test Widget

Start API functions and the Dev server. Run npx vercel dev to launch the server locally. Open test-widget.html in your browser to test conversation flows.

RAG & Embedding Pipeline

When a visitor asks a question, the API routes it to api/chat/index.js. The system performs the following sequence:

  1. Calls OpenAI Embeddings API (text-embedding-3-small) to transform the query into a 1536-dimensional float vector.
  2. Queries Supabase database utilizing the custom PostgreSQL RPC function match_chunks which implements vector cosine distance matching (<=> operator).
  3. Filters matches by the specific school_id to ensure institutional data privacy, keeping chunks above a similarity threshold (default: 0.4).
  4. Injects the matched document text chunks as a context block in the system prompt for OpenRouter's anthropic/claude-3.5-sonnet model.
  5. Streams the generated output token-by-token back to the browser using Server-Sent Events (SSE).

🟢 Real-Time Presence & Escalation Alerts

Agent status, lead "online" indicators, and the escalation alert system are all derived server-side from activity recency rather than a manually-picked value — so nothing can get stuck stale. The single source of truth for presence is src/utils/presence.js.

🟢 Agent Online / Away (Automatic)

The admin Sidebar sends a heartbeat (PATCH /api/admin/me with { heartbeat: true }) every 20 seconds while the dashboard is open. Any endpoint reporting agent status — /api/admin/users, /api/admin/agent-stats, and the widget's adminsOnline flag — calls computeAgentStatus(profile):

  • updated_at within 45s → online
  • updated_at older than 45s → away
  • profile status = 'invisible' → always invisible, regardless of heartbeat

"Invisible" is the only manual override left — there is no manual "online"/"away" toggle, since both are now derived automatically.

👤 Lead / Visitor Presence

The widget already polls the backend while a chat is open — those polls now double as presence heartbeats instead of adding new traffic:

  • GET /api/chat/status?sessionId=… — every 30s outside escalation, touches conversations.updated_at
  • GET /api/chat/messages?sessionId=… — every 3s while escalated, does the same

The Team & Activity page treats a conversation as inactive once updated_at is more than 2 minutes old (previously 10 minutes) — tight enough to reflect an open browser tab, not just recent messages.

🚨 Escalation Detection

detectEscalation() in src/services/llm.js runs directly on the visitor's raw message (not just the AI's reply), so it triggers regardless of how the AI chooses to respond. It combines:

  • A static phrase list — complaint, refund, real human, live agent, customer service, etc.
  • A regex covering verb + role combinations — "talk / speak / chat / want / need / connect me / reach" + "a human / person / someone / agent / admin / staff / manager"
  • The AI's own [ESCALATE] token, appended per its system prompt when it recognizes an escalation-worthy request

This means phrasings like "I want to speak with a human", "can you reach admin", or "is there a live person available" all trigger reliably, independent of the model's wording that turn.

🔔 Ringtone & Popup Alerts

EscalationContext.jsx polls pending escalations every 5s. While there's an unacknowledged pending escalation, it plays a synthesized tone (admin/src/utils/notificationSound.js) on a repeating 3-second interval — like an incoming call — until an admin views or dismisses it.

EscalationAlertPopup.jsx is mounted globally in App.jsx (hidden only on /login and /set-password), so it fires on any page the admin is on, regardless of their online/invisible status — as long as the dashboard tab is open.

Who sees what: The Team & Activity page (/agents) is visible to every admin — live agent status and conversation load included. Only super_admin accounts see the invite / role-management controls at the top of that same page; the API endpoints for invite, role change, and removal remain server-side gated via requireSuperAdmin either way.
❓ Troubleshooting FAQ

Review standard issues reported during build, staging testing, and production runtime.

The Chat Widget is not displaying on the webpage. +
Verify that `window.SchoolBotConfig` is set correctly BEFORE the `widget.js` script tag in the HTML. Ensure `schoolId` matches either `'backock'` or `'abu'` exactly, and `apiUrl` points to your deployed Vercel domain.
The AI bot gives incorrect or stale answers. +
This happens when the knowledge base has stale contents. Log into the Admin Dashboard, navigate to the **Knowledge Base** section, select your school, delete the outdated document, and upload the updated PDF or text file.
Invitations sent to team members result in expired links. +
Supabase Auth invitation links expire after 24 hours. A Super Admin must navigate to **Team Members**, click "Remove" next to the user, and then issue a new invite with the corrected email address.
Vercel build fails with a 12-serverless function limit error. +
Vercel Hobby accounts restrict builds to a maximum of 12 serverless function files. If adding new features, route multiple sub-resources using method switches within a single API endpoint (e.g., how the documents endpoint handles GET, POST, and DELETE inside api/documents/index.js).
🔒 Security, Compliance & Data Isolation

The School RAG Agent is built with enterprise security principles in mind. As a multi-tenant platform serving distinct educational institutions, the following policies are strictly implemented:

Role-Based Access Control (RBAC)

Admins can only view chats, leads, and documents. Only accounts explicitly designated as super_admin in the admin_profiles database row can manage user accounts, change roles, or delete administrative credentials.

Supabase Row-Level Security (RLS)

Database queries executed directly from the client utilize the Supabase anon key and are isolated using RLS policy USING (auth.uid() = id) to ensure admins cannot fetch data for other profiles.

Data Isolation Policy: All database rows in the leads, conversations, escalations, and document_chunks tables are tagged with a foreign key reference to schools.id. Serverless functions filter all RAG queries and administrative analytics by the active school scope, preventing cross-tenant leakage.

🔑 Password Recovery & Change

Admins who forget their password use "Forgot password?" on the Login page, which calls supabase.auth.resetPasswordForEmail() and reuses the same /set-password page built for invite links. Logged-in admins can change their password any time via Change Password in the Sidebar.

💪 Server-Side Password Policy

Password rules (length, uppercase, lowercase, number, symbol) are enforced by Supabase's own Auth password policy — not just the client-side checklist — so they can't be bypassed by calling the API directly. Supabase's leaked-password check (HaveIBeenPwned) is also enabled. Changing a password while already logged in requires the current password (current_password field), per Supabase's "Require current password when updating" setting.
