Executive Summary

Edutech AI Team designed, built, and deployed a full-stack AI-powered admissions chatbot for two Nigerian universities — Babcock University and ABU (Ahmadu Bello University). The system includes an embeddable chat widget, a backend AI engine powered by Retrieval-Augmented Generation (RAG), and a multi-role admin dashboard with live escalation support, lead management, and team access control. The platform is fully deployed on Vercel and operational.

1. Project Background & Objectives

Edutech engaged the Edutech AI Team to build an AI chatbot system for their partner universities. The primary goal was to reduce the volume of repetitive admissions enquiries handled by staff by providing prospective students with instant, accurate answers 24/7 — and to route complex or unresolved queries directly to a human support agent.

1.1 Core Objectives

  • Deploy an AI chatbot on university websites with zero friction for website administrators (simple two-line embed)
  • Answer prospective student questions about admissions, programmes, fees, and campus life using a custom knowledge base
  • Capture student leads (name, email, phone) automatically during chat
  • Provide a live human escalation path when the AI cannot resolve a query
  • Give university staff a branded admin dashboard to manage conversations, respond to escalations, and update content
  • Support multiple institutions from a single platform with school-specific data isolation
  • Implement role-based access control for the admin team

2.1 Data Flow — Student Chat

  1. Student opens webpage → widget.js loads → chat bubble appears
  2. Student fills contact form (name, email, phone) → lead created in Supabase
  3. Student sends message → POST /api/chat
  4. Backend performs vector similarity search on the knowledge base (RAG)
  5. Relevant document chunks are injected into the LLM prompt as context
  6. LLM generates a streaming response → sent back as Server-Sent Events (SSE)
  7. Widget renders the response token-by-token in real time
  8. If student requests human agent → conversation escalated → admin notified

2.2 Data Flow — Admin Live Chat

  1. Admin opens Escalations page → clicks escalated conversation
  2. Admin types reply → POST /api/admin/reply
  3. Reply is appended to conversation messages array in Supabase with admin's name
  4. Widget polls /api/chat/messages every 3 seconds
  5. New admin message is displayed to the student in real time (within 3–4 seconds)

4. Features Delivered

🤖

RAG-Powered AI Chat

The bot uses Retrieval-Augmented Generation to answer questions from uploaded knowledge base documents. Vector similarity search identifies the most relevant document chunks, which are injected as context into the LLM prompt. This ensures answers are grounded in actual school information rather than hallucinated.

⚡

Real-Time Streaming Responses

Bot responses stream to the widget token-by-token using Server-Sent Events, giving a live typing effect. This eliminates perceived wait time and improves the student experience significantly.

👥

Lead Capture

Every new visitor is prompted to submit their name, email, and phone number before chatting. This creates a lead record linked to all their conversation history. Leads are viewable and filterable in the admin dashboard.

🚨

Human Escalation & Live Chat

When a student requests a human agent (or the bot detects it cannot help), the conversation is escalated. The admin dashboard shows all open escalations. Admins can reply in real time — messages are delivered to the student's chat widget within 3–4 seconds via polling. Admin names appear on each message.

🏫

Multi-School Support

A single deployment serves both Babcock University and ABU. The widget can be configured for one school or both simultaneously. All data (leads, conversations, documents) is tagged by school. Admin staff can filter all views by school using the sidebar selector.

📚

Knowledge Base Management

Admins can upload, view, and delete documents from the Knowledge Base. Uploaded documents are automatically processed — text is extracted, chunked, and stored as vector embeddings in Supabase. The bot immediately begins using new documents to answer questions.

🔐

Multi-Admin RBAC (Role-Based Access Control)

Two role tiers: Super Admin (full access including user management) and Admin (operational access — replies, knowledge base, leads). Super Admins can invite new team members by email, assign roles, change roles, and remove access. Invite links use Supabase Auth's invite-by-email system with a custom set-password flow.

📊

Analytics Dashboard

The dashboard displays real-time counts of leads, conversations, escalations, and open escalations — filterable by school. Gives administrators an at-a-glance view of chatbot activity.

🌐

Embeddable Widget

The chat widget is compiled to a single self-contained JavaScript file (IIFE format, ~160KB gzipped to ~51KB). It is embedded with two HTML lines and works on any website platform without framework dependencies.

7. Widget Embed System

7.1 Build Process

The widget is built as a self-contained IIFE (Immediately Invoked Function Expression) using Vite in library mode:

  • Entry: widget/src/embed.jsx
  • Output: widget/dist/widget.js (~160KB, gzips to ~51KB)
  • React and all dependencies are bundled inline — no external dependencies required on the host page
  • CSS is inlined into the JS bundle
  • After build, widget.js is copied to admin/dist/widget.js and served as a static file from Vercel

7.2 Configuration Schema

window.SchoolBotConfig = {
  // Option A: Multi-school (user selects school in widget)
  schools: [
    { id: 'backock', name: 'Babcock University' },
    { id: 'abu',     name: 'ABU (Ahmadu Bello University)' }
  ],

  // Option B: Single school
  schoolId: 'backock',  // OR 'abu'

  // Required
  apiUrl: 'https://school-rag-agent.vercel.app',

  // Optional
  theme: { primaryColor: '#1a73e8' }
};

7.3 Vercel Static File Serving

The vercel.json catch-all rewrite /(.*) → /index.html applies only when no matching static file exists. Since widget.js is present in the output directory (admin/dist/), Vercel serves it as a static asset directly — the rewrite never applies to it. This ensures the widget URL is always reliable and served from Vercel's global CDN.

8.2 Context Providers

  • UserContext — loads the current admin's profile from Supabase on login; provides name, email, and role to all components
  • SchoolContext — manages the active school filter; persists selection across page navigation

8.3 Invite Flow (Set Password)

When a Super Admin invites a new user, Supabase sends an invite email containing a one-time token URL. The URL's redirectTo parameter points to /set-password on the admin dashboard. When the invited user clicks the link:

  1. Supabase validates the token and establishes a session (auto-detected by the Supabase JS client from the URL hash)
  2. The SetPassword page detects the active session via onAuthStateChange
  3. User enters and confirms a password → supabase.auth.updateUser({ password })
  4. On success, user is redirected to /dashboard

9. Security Implementation

9.1 Authentication

  • All admin API endpoints validate a Supabase JWT on every request via supabase.auth.getUser(token)
  • The service-role key (used for admin operations like invite/delete) is stored server-side only — never exposed to the browser
  • Admin app uses the Supabase anon key for client-side auth — the anon key has no elevated privileges

9.2 Authorisation (RBAC)

  • Every admin API endpoint calls requireAuth() to verify the JWT is valid and the user exists in admin_profiles
  • Super Admin-only endpoints additionally call requireSuperAdmin() which checks role === 'super_admin'
  • A Super Admin cannot delete themselves — self-deletion is blocked server-side
  • Frontend route guards redirect non-super-admins away from the Users page

9.3 Row Level Security (RLS)

  • admin_profiles has RLS enabled with policy: USING (auth.uid() = id)
  • Each admin can only read their own profile row via the anon/client key
  • All other profile reads are done server-side using the service-role key

9.4 Public Endpoints

  • Chat endpoints (/api/chat, /api/chat/start, /api/chat/messages) are public (no auth required) — they serve the widget
  • Rate limiting is handled at the Vercel infrastructure level
  • No sensitive data is returned from public endpoints — only conversation messages and bot responses

11. Issues Resolved During Build

Widget Not Appearing — Embed Config Validation Bug
The multi-school schools[] config was rejected because the validation checked !config.schoolId (always true for multi-school). Fixed by updating validation to: !config.schoolId && !Array.isArray(config.schools).
Widget.js 500 Error — Serverless fs.readFileSync Failure
The original approach served widget.js via an API function using fs.readFileSync. Vercel serverless functions cannot access files outside their bundle. Fixed by removing the API function entirely and copying widget.js to admin/dist/ during build so it is served as a static CDN asset.
Vercel 12-Function Limit Exceeded
Adding new endpoints (reply.js, messages.js, users.js) pushed the function count to 14. Resolved in two steps: deleted the now-redundant api/widget.js; consolidated three document endpoints (delete, list, process) into a single method-routed api/documents/index.js. Final count: exactly 12.
Escalation Notification Not Delivered to Visitor
When the bot escalated a conversation, the notification message was stored in the database but not included in the SSE response. The widget had no way to display it immediately. Fixed by pushing the notification into the messages array before the SSE done event and including the full messages array in the event payload.
Ghost Empty Bubble During Escalated Stage
The widget always added an empty placeholder bubble before the SSE stream started, even during the escalated stage where no streaming occurs (messages are returned wholesale). Fixed with a stage check: if (stage !== 'escalated') before adding the placeholder.
Invite Link Pointing to localhost:3000
Supabase defaulted invite links to the project's Site URL, which was set to localhost:3000. Fixed by: (1) updating the Supabase Site URL to the production Vercel URL, (2) adding redirectTo to the inviteUserByEmail call using req.headers.origin, and (3) building a dedicated /set-password page in the admin app.
process.env.NODE_ENV Undefined in IIFE Build
The widget IIFE build failed to replace process.env.NODE_ENV at build time, causing runtime errors. Fixed by adding define: { 'process.env.NODE_ENV': '"production"' } to the Vite config.

12. Recommendations

12.1 Immediate Actions

  • Upload knowledge base content — The chatbot's quality is directly proportional to the richness of its knowledge base. Upload comprehensive, current documents for both universities as a priority.
  • Test the full escalation flow — Have a team member simulate a student chat through to escalation and confirm admin reply delivery end-to-end.
  • Configure Supabase email sender name — Set up custom SMTP (e.g., Resend or SendGrid) in Supabase Project Settings to send invite emails from "Edutech Support" with a branded domain.

12.2 Short-Term (1–3 Months)

  • Custom domain — Map a branded domain (e.g., admin.eabtconnect.com) to the Vercel deployment
  • Admin notifications — Add email or push notification when a new escalation arrives, so admins don't need to check the dashboard constantly
  • Escalation SLA tracking — Display response time in the escalations view to help enforce service-level commitments
  • Analytics export — Add CSV export for leads and conversations

12.3 Long-Term

  • Vercel Pro upgrade — Moving to Vercel Pro removes the 12-function limit and adds advanced analytics, password protection, and preview deployments
  • Additional schools — The architecture is multi-tenant. New schools can be onboarded by adding a new schoolId slug and uploading their documents
  • Mobile admin app — A React Native or PWA version of the escalations view for on-the-go responses
  • Conversation analytics — Track common questions by topic to identify knowledge gaps and inform content strategy
  • Automated follow-up — Trigger automated email sequences to leads after their chat session
